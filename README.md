### Компиляторный стек для Ascend NPU (Huawei)
*Декабрь 2025 – Июль 2026*  

Проект с ключевым заказчиком успешно завершён (релиз продукта), я отвечал за качество и производительность компилируемого кода. Дальнейшее трудоустройство в другие команды оказалось невозможным из-за отсутствия открытых вакансий.
- В пайплайне `TTIR` -> `TTADAPTER` (custom Triton-Ascend output for AscendNPU-IR backend) -> `HFusion` -> `HIVM` -> `BiSheng compiler backend`, занимался AscendNPU-IR частью - `HFusion`, `HIVM`.
- Обеспечиваю корпоративную безопасность и чистоту интеллектуальной собственности: чётко разделяю собственный код и код из приватных репозиториев.
- Создавал Merge Request’ы с исправлениями и новыми низкоуровневыми интринсиками (intrinsics) Ascend NPU, следуя внутренним стандартам оформления.
- Владею инструментарием `CANN Toolkit` (как внутренней сборкой, так и публичными релизами): понимаю назначение компонентов `ACL`, `op-compiler`, `ccec` и их взаимодействие при компиляции.
  * В качестве хобби, для упрощения отладки коммуникации с драйвером, сделал свою реализацию `CANN Toolkit`, полностью работающую с оригинальным `torch-npu`, на CPU, без утечек памяти: [от оригинального toolkit достались только заголовочные файлы](https://github.com/VectorASD/QuickStart/tree/master/llvm/my_acl).
- Координировал работу с командами через WeLink, выполнял задачи в рамках рабочего проекта, оперативно реагирую на запросы.
- Работал с тикетами: анализировал конфликтующие/устаревшие записи, готовил отчёты о проверках с заключениями о необходимости исправлений.

Репозитории, с которыми я работал:
- https://github.com/Ascend/AscendNPU-IR
- https://github.com/Ascend/triton-ascend
- https://github.com/Ascend/pytorch (`torch-npu`)

### НИЛ ЗИС / СибГУТИ (Научно-исследовательская лаборатория защищённых информационных систем)
*Март 2026 — сейчас*

Участвую в НИР «Криптосистемы с математически доказанной надёжностью» (руководитель Б.Я. Рябко, администратор А.Н. Фионов) с целью внедрения разработанной технологии в программное обеспечение лаборатории и подготовки материалов для магистерской диссертации.
- Провожу исследование методов обратимого сокрытия данных (RDH-стеганография) с применением линейной хэш-функции; разрабатываю модифицированный алгоритм встраивания информации.
- Реализую алгоритм на Python/C++, провожу экспериментальную оценку: расчёт PSNR, SSIM, построение гистограмм распределения ошибок, сравнение с базовыми методами.
- Готовлю материалы для регистрации программного продукта и публикации результатов.

### Симулятор логических схем (курсовой проект, монетизирован)
*2023*

Создал с нуля симулятор логических схем на C#/Avalonia.
- Реализовал визуальный редактор логических схем с собственным менеджером соединений.
- Впервые применил мьютексы из-за их **острой** необходимости: поток редактора и симулятора боролись за один и тот же контейнер, что было основным источником поломок ровно до того момента, как я познакомился с замкáми/mutex.
- Настроил автоматический подсчёт версий (билдов).
- Разработал генератор ER-диаграмм на основе C#-рефлексии.
- Реализовал архитектуру по модели MVVM (Model → ModelView → View) с ациклическим графом зависимостей.
- Вёл разработку по модели Gitflow (main, develop) с указанием версий (билдов).
- Проект продан 20+ студентам и сопровождался технической поддержкой до конца сессии.

### Плагин чанкированной загрузки CLIP для ComfyUI (ComfyUI-VectorASD)
*Проект 2025 года, публичный релиз*  
Решил фундаментальную проблему нехватки видеопамяти при работе с большими текстовыми энкодерами в Stable Diffusion. Разработал плагин, который разбивает CLIP-модель на управляемые блоки, загружает их последовательно и освобождает VRAM, позволяя запускать пайплайн на картах с ограниченными ресурсами.

**Ключевые инженерные решения:**
- **Собственный парсер и планировщик загрузки:** Реализовал алгоритм, который разбирает бинарный safetensors-формат, строит дерево тензоров через реконструированную логику (вдохновлённую минифицированным JS с Hugging Face) и автоматически нарезает модель на чанки с лимитом по VRAM, задаваемым пользователем. Никакой зависимости от Google Protobuf — только прямое чтение заголовков и работа со смещениями.
- **Пайплайн обработки текста «по расписанию»:** Переписал внутренний цикл инференса ComfyUI так, чтобы он выполнял проход по блокам энкодера порциями, сохраняя промежуточное состояние (эмбеддинги, attention mask) и передавая его между загрузками. Это потребовало глубокой модификации `umt5_xxl` и аккуратного управления контекстом выполнения.
- **Оптимизация многопоточности в пользовательском интерфейсе:** В JavaScript-расширении для графа узлов реализовал контролируемое изменение количества входов и динамическое переименование префиксов. Применил сортировку и лимитирование входов без потери состояния, что демонстрирует работу с DOM-событиями и внутренним API ComfyUI на уровне, близком к разработке операторских панелей.
- **Инструменты отладки и визуализации:** Написал утилиты для анализа тензоров: расчёт SHA-256 дайджеста, ASCII-визуализация эмбеддингов (посимвольная и «прыжковая» на основе угловых смещений), глубокое сравнение сложных структур с защитой от циклов. Это показывает заботу о качестве и привычку к созданию прозрачных инструментов контроля.
- **Лицензионная чистота:** Впервые провёл глубокий разбор лицензий (MIT, Apache 2.0, неявные условия) при создании публичного проекта. Корректно оформил использование модифицированных компонентов ComfyUI, реконструированного кода и указал авторство, продемонстрировав ответственное отношение к интеллектуальной собственности.

[Репозиторий ComfyUI-VectorASD](https://github.com/VectorASD/ComfyUI-VectorASD)
